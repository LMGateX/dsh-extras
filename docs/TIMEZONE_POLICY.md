# 浏览器时区防泄露：请求上报跟随 DSH 本机

日期：2026-11-16。状态：**窄范围已固定，已授权隔离开发、push、发版和本机安装；执行证据另行记录**。本版取代上一版“三模式时间策略”和时间注入治理要求。

## 1. 唯一目标

**避免浏览器自动检测到的时区进入请求；让新增自动时区上报与运行 DSH 的本机保持一致。**

这里的“本机”是 DSH 宿主进程所在机器，不是访问 GUI 的浏览器所在机器。使用宿主进程实际解析到的 IANA 时区；若其已有 `TZ` 配置，沿用，不修改它。功能不是隐藏宿主时区，也不是让所有工具使用一个新造的时间环境。

任意固定成与宿主不同的时区不推荐：shell、工具及其他宿主上下文仍可能自然呈现本机时区，形成差异和额外泄露面。**首版不提供任意 fixed 时区选择器；不是 browser/fixed/host 三模式产品。**

## 2. 功能范围

### 2.1 仅改变自动上报的数据来源

启用“请求时区跟随 DSH 本机”后：

- 自动生成的请求时区字段（例如 `clientTimeZone`）使用 DSH 宿主时区，而不是浏览器检测值。
- 检查现有普通、queue/steer、人工子 agent prompt 及其他使用相同自动采样函数的发送分支，避免遗漏浏览器取值路径。
- 按[0.7.0 接口契约](HOST_TIMEZONE_070.md)在独立资源命名空间中替换精确字节校验过的自动采样函数，不修改原生安装文件。不能只改提示文字或另加一条相反的有效时区说明。
- 不把真实浏览器时区挪入别名字段、诊断 payload、请求 metadata、模型上下文或新增日志。本功能无需为审计而采集、持久化真实检测值。
- 浏览器本地显示或用户自己明确输入的文本，不等同自动时区上报；本功能不扫描/改写任意文本。

宿主时区不可可靠获得时，报告功能不可用，**不得偷偷回退为浏览器时区并宣称已启用保护**。显示已启用/不可用状态即可，无需引入一套通用时区策略或来源审计系统。

### 2.2 原生提示的关系

`Browser time zone for this request` 若由 DSH 按该字段生成，应自然反映上报的宿主时区。本功能不直接替换这行文本、不更改 renderer，也不再独立注入另一个时钟。

例如：DSH 本机为 `Asia/Singapore`，浏览器恰好为 `Asia/Shanghai`，启用后新增自动上报值为 `Asia/Singapore`。两者当前偏移相同也不能仅比较 `+08:00`；要检查具体 IANA 值及自动字段中是否还携带浏览器检测值。

## 3. 明确不做什么

| 范围 | 裁定 |
| --- | --- |
| 何时/何处注入时间、原生十分钟刷新间隔 | **DSH 负责；不改、不强制刷新、不绕过节流** |
| retry/user reader、missing/mixed、同轮合并 | 沿用原生语义，不为此功能改 source 身份、reader 或冲突算法 |
| goal/job 自动轮、spawn/fork、SDK/ACP/headless | 不建立新的时区继承、快照或传播协议；无浏览器自动上报的路径保持原样 |
| compaction、恢复、模型切换、provider 重试 | 不要求新增保真槽，不改原生重放、摘要、准入或重试规则 |
| shell / PowerShell / terminal / PTC | 继续使用各自原有的本机/运行环境；不改 `TZ`、`Date`、`Intl` 或工具参数 |
| 其他直接引用 DSH 本机时区的逻辑 | 不是本功能要修的问题，保持其本机引用方式 |
| 定时任务规则、UTC occurrence、外部 MCP/web/Office 数据 | 保持原始语义，不重排任务、不统一换算、不重写结果 |
| 聊天时间显示、日期分组、任务编辑器、Chime 勿扰时段 | UI-only 显示与手选规则不联动；任务编辑器的自动默认时区会进入 create 请求，属于本次同一来源修正，不可冒充 UI-only 排除 |
| 配置与历史 | 不新增每会话策略、policyRevision、检测值持久化或全套审计；只保留实现该开关所需的最小配置 |

若后续发现某个工具**主动把浏览器自动检测值转送到请求**，它属于同一泄露入口，应在原发送位置修正来源。仅仅使用宿主时区、输出日期或返回外部时间，不构成这样的缺陷。

## 4. 保证边界与实施缺口

- 保护的是启用后新增的自动时区上报，不是全请求匿名化，不保证消除用户文本、旧会话历史或外部内容中出现的浏览器时区。
- 原生历史中已有旧时区时，DSH 可能继续把它作为历史内容发送；本功能不回溯清洗历史，不为清除此现象介入时间注入。验证新增字段时优先使用干净会话，另明确已有会话的历史限制。
- 新字段采用宿主值不等于“下一次模型请求必定新注入时间”：原生刷新与复用逻辑保持不变。
- 宿主本身的系统时区、进程 `TZ` 或各工具环境若本就不一致，不由本功能重配；不把宿主一致性改造成全局环境治理任务。
- 当前审计的公开 Host facts 没有时区字段，内置发送函数直接采样浏览器；需验证取得可信宿主时区与替换上报来源的最小 seam。这不是新增时间注入接口的理由。
- 承载能力为默认关闭的 `host-timezone` 模块，精确 DSH 0.2.2-rc.3 / Extras 0.7.0、六模块七产物；启停需完整刷新页面，已打开旧页面不宣称受保护。用户已明确授权隔离/subagent 开发测试、push、发版及验证后的本机安装；详见[当前交付契约](HOST_TIMEZONE_070.md)。

## 5. 收窄后的验收

旧版 TZ-01～TZ-14 因用户明确纠正功能目标而撤回，不再作为此功能的门槛；并非降低原有已发布功能的安全或回归验收。未来仅需本功能相关的 HTZ-*：

| ID | 必须提供的证据（尚未执行） |
| --- | --- |
| HTZ-01 | 宿主与浏览器 IANA 时区不同，启用后所有受影响自动发送分支上报宿主值；默认检测函数不再把浏览器值带入这些新增请求 |
| HTZ-02 | 实际序列化字段、其新增持久来源/模型可见 metadata 不额外含浏览器检测值；不以换字段名或仅改展示冒充防泄露 |
| HTZ-03 | 宿主时区不可用或连接更换时不误用浏览器/旧宿主值；明确报告保护不可用；不提供任意 fixed 覆盖入口 |
| HTZ-04 | 不注册额外时间注入，不修改原生刷新、reader、续跑、压缩及重试规则；已有宿主时区引用与工具环境保持原状 |
| HTZ-05 | 干净会话验证新增上报；已有历史、用户明文和 UI-only 显示的限制如实说明，不承诺历史去泄露 |
| HTZ-06 | 在 disposable HOME/DSH_HOME/profile 与临时端口验证实际打包客户端；支持版本精确声明，不操作生产 GUI |

不要求为这项窄功能重新实现或逐项认证完整的 fork、压缩、定时、Office、PTY 等时间语义；只验证本功能没有介入它们。
