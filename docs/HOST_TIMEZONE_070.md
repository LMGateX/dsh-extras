# Host time-zone privacy — Extras 0.7.0 implementation/release contract

Fixed before runtime implementation, 2026-11-16. The user accepts the narrowed [privacy scope](TIMEZONE_POLICY.md), then explicitly authorizes: documentation, development/testing in isolated environments and subagents, push, release, and installation into this machine’s DSH. This supersedes documentation-only/no-install restrictions only for the present capability and final verified installation. No GitHub Actions or npm publication.

## Scope and baseline

- Prevent browser-detected zones from being automatically reported to requests; use the DSH host process zone. No arbitrary fixed selector, global Intl/Date/TZ changes, extra time injection, refresh/reader/retry/goal/compaction changes or tool environment rewriting.
- Start from remote main `2090e8c66a8ba8e0545a39ac740e00d4241fc908` (released Extras 0.6.1, exact published DSH 0.2.2-rc.3 / Cordis 4.1.0), not the older local 0.4.0 checkout. Preserve every currently shipped module and shared-policy owner contract. The two prior timezone documentation commits are rebased onto this current baseline; original main/source checkout remains untouched during development.
- Add one independently enabled, default-off `host-timezone` module and its real standalone `dsh-extras-host-timezone` distribution from the same feature source. Extras 0.7.0 therefore has six modules and seven synchronized archives. No new legacy source is invented; upgrade must preserve all previous settings and add the new capability disabled until explicitly enabled.
- Prompt telemetry and automatic schedule defaults must be distinguished from user-selected/stored task rule zones. Do not overwrite explicit TZID/time_zone rules at the RPC boundary: automatic-default provenance is lost there.

## Seam decision gate

Primary-source investigations are in [host seam research](research/HOST_TIMEZONE_HOST_SEAM.md) and [client seam research](research/HOST_TIMEZONE_CLIENT_SEAM.md). The native /api intercept slot is already owned; host payload replacement is also too late to prevent wire disclosure. Select a narrow **served-artifact compatibility adapter**, not a time-context hook or global browser API override.

Exact rc.3 public interfaces: clientModules.graph(), clientPath(id), fetchBundle(Request), webServer.register(resource), and webserver/index-inject. Native bootInjections emits structured global __DSH_BOOT__ plus preload/script-src rows. Clone and retarget only target-containing combo/entry references to an owned /extras/host-timezone resource namespace, leaving the native graph and files untouched. The owned resource delegates the original /plugins request to fetchBundle, verifies exact known package version/raw SHA256 and unique function anchors, and replaces only automatic browser sampling/default construction in session-controller and schedule client artifacts. Preserve explicit stored/user-selected rules. Use distinct non-immutable/no-store responses; never serve changed bytes under the native immutable revision URL. The resource layer does not monkeypatch fetchBundle; the later source-validity correction adds only the mandatory per-instance Connection admission adapter.

Native HMR graph/rebuild notifications have no public graph-filter hook and can advertise native raw target combos again. Therefore acquire an additional effect-owned exact `/plugins/` guard while enabled: target-containing native JS combos return a bounded no-store reload-required refusal, never raw or patched bytes under an immutable native URL; unrelated combos delegate unchanged. The owned namespace delegates directly through fetchBundle and remains the only protected delivery path. A foreign route owner causes rollback of only this mount’s acquired routes and unavailable status. Full reload rebuilds protected references from the current native graph.

A served page uses the host process IANA zone, not a query-supplied fixed override; host-zone identity must participate in owned URL/cache-generation validation. Reject unsupported targets or mismatched transform expectations rather than silently serving unprotected bytes from the owned path. Report unavailable/reload-required accurately. Already-open pages/native cached scripts are outside immediate activation: enable/disable and a subsequent host-process timezone change require full page reload, and old unmodified pages are not claimed protected. The adapter registers no pre-step/time injection/reader/refresh/retry behavior and changes no tool environment.

## Review-driven source-validity correction (fixed before implementation)

Independent review found a release-blocking stock-web reconnect path: an active native module retained at the same revision can report a prior host zone after same-origin server replacement. A real packed-browser restart test reproduced an unexpected serialized prompt. A second actual Chromium cache test reproduced the browser zone after raw immutable target factories re-materialized without reaching the server guard. The initial implementation also failed to recover from a live host-zone change on full reload. These are defects of the narrow source guarantee, not reasons to widen time policy or waive HTZ-03.

- Host source generations become immutable {epoch, zone, pinned artifacts, target graph stamp, mappings}. Fresh index generation synchronously prepares a new source from already verified bytes when the host zone changes and retires old references. Resource/proof requests capture and recheck their generation after awaits. Target removal/rebuild/re-add rotates only this source proof; native graph objects stay untouched.
- Protected boot adds only a readonly `__DSH_EXTRAS_HOST_TIMEZONE_PAGE__` descriptor with protocol `dsh-extras.host-timezone.v1`, opaque source epoch, owned generation-specific proof URL and present target IDs. A GET proof is no-store and recognizes only the current owned epoch with unchanged host zone, versions/bytes and target graph. It returns approval/refusal, never a replacement zone for an old page. No browser facts, persistence, policy revision or inheritance protocol are introduced.
- Both transformed native target exports carry a readonly, non-enumerable, frozen `__dshExtrasHostTimezoneSource = {protocol, epoch}` marker. The transform gains a required fifth `sourceEpoch` argument for protected host use. One selected-client page guard uses public `connection.generation` / `connection.state` snapshots/subscriptions and exact rc.3 native module-loader record/export identities plus entry-sync state. Initial admission verifies transformed markers and the expected epoch. Initial connected-before-generation publication is warming, not invalid. After binding, connection loss/replacement, changed/missing target record/export, raw cached factory materialization, source-proof refusal or owner disposal permanently revokes the page until full reload. Raw same-revision graph advertisements alone do not revoke unchanged protected exports or reauthorize new raw exports.
- Before serialization, a mandatory version/descriptor/ownership-limited adapter of the current Connection instance own `rpc.call` admits only /api session/prompt, subagents/prompt, schedule/create and time-bearing schedule/edit (update with timing) after a fresh proof. Every unrelated RPC delegates unchanged. Sensitive calls fail closed while syncing, not ready or revoked, and recheck connection/generation/module identity after asynchronous proof. The adapter does not change payloads, explicit task rules, receivers, signals or retries; native Gateway failure settlement preserves Session echo cleanup and task drafts. This also gates a cached raw sampler that no longer calls a source helper.
- A previously protected page may retain a refusal-only admission tombstone after client HMR/disposal until full reload; it has no listeners, rearming, rewriting, polling, automatic reload or draft clearing. Fresh disabled pages register no feature guard. This narrow irreversible-loaded-page exception replaces the zero-effects-disabled shorthand here; server hooks/routes still fully dispose. The UI distinguishes server readiness, current-page validity and reload-required/unavailable.

These compatibility details remain confined to exact served-web rc.3. Native module-loader record fields are a declared internal-contract, not a newly claimed stable extension hook. Missing or foreign shapes/owners are unavailable, never raw fallback. Real cache/restart and independent re-review gates are mandatory; previous passing counts certify only the prior candidate.

## Pre-agreed test surfaces

The accepted HTZ gates use the exported Cordis feature interface (enable/disable/unload/status and host facts), actual emitted/packed client loading and serialized RPC requests from a native isolated GUI, plus unchanged native tool/task behavior. These are the test seams for vertical red/green slices; fake-port characterization alone cannot certify wire privacy. Test both browser and host IANA identities different but same offset, a cross-day/DST example, no browser value in added metadata, explicit task rule preservation, current connection/reload limits and unavailable support. Do not introduce new lifecycle semantics to make native clock injection refresh.

## Delivery gates

1. Run exact npm graph preflight, typecheck, focused tests regularly, complete source suite, all seven packed clean consumers and actual isolated native-browser gates. Build and install hosts only with explicit disposable HOME/DSH_HOME/profile/XDG/cache/tmp paths and non-production ports. Runtime implementation and test tasks run in subagents with disjoint edit ownership.
2. Independent Standards and Spec reviews, final diff review and rerun affected tests. Record real commands/results and limitations. No claimed native/browser coverage without execution.
3. Update final version/readme/declarations/provenance, rebuild/repack, verify all archives/checksums. Fast-forward remote main without overwriting concurrent work; new annotated v0.7.0 tag at final tested commit. Publish seven archives and SHA256SUMS as a formal GitHub release, then independently download and verify actual remote bytes/identity.
4. Only after those gates: discover the user-authorized local target through native interfaces, make a restricted backup outside Git, install through native plugin management, preserve unrelated personal settings, explicitly enable only the new capability as needed for the user’s request. Do not replace the native DSH installation or patch node_modules. Verify installed vs reload-required vs actually served/active separately. Keep rollback instructions and the prior artifact/config. A reload/restart requirement must be reported rather than falsely claiming protection for an already-loaded old page; do not unexpectedly restart this active conversation’s host.
